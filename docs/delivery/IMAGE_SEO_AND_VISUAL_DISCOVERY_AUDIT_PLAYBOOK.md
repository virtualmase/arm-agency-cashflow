# Image SEO and Visual Discovery Audit — Delivery Playbook

**Offer type:** Bounded diagnostic and remediation plan

**Purpose:** Help a client improve the accessibility, performance, factual context, and public discoverability foundations of meaningful image assets. The service does not promise image rankings, rich-result appearance, AI citations, traffic, or any external platform outcome.

## 1. Fit and Scope Gate

| Good fit | Poor fit or no-go |
| --- | --- |
| The client has public images, product media, diagrams, editorial visuals, or preview images that support a real buyer journey. | The client wants generic images added solely to “do image SEO.” |
| A content or technical owner can confirm source, rights, facts, and intended page context. | No one can confirm image rights, what a visual depicts, or whether claims embedded in it are true. |
| The client wants a prioritized remediation plan and can implement or authorize the changes. | The client asks for a guarantee of rankings, visual-search traffic, or generative AI visibility. |
| The client can share a bounded URL list and, where relevant, CMS/CDN access or exports. | The request requires a large-scale DAM migration, unrestricted content production, or rights clearance beyond the agreed diagnostic. |

## 2. Inputs

| Required input | Why it matters |
| --- | --- |
| Priority URLs and buyer journeys | Keeps the review connected to decision-making pages rather than an unbounded asset inventory. |
| Image inventory or crawl/export where available | Establishes what exists and avoids assumptions. |
| Source and rights information | Prevents misuse of client, employee, licensed, or generated visual assets. |
| Brand and claims owners | Ensures that captions, descriptive context, and metadata remain factually accurate. |
| Technical implementation owner | Confirms who can change HTML/CMS components, CDN settings, sitemaps, or preview metadata. |

## 3. Delivery Method

| Step | Work | Output |
| --- | --- | --- |
| 1. Intake and segmentation | Group priority visuals by page, purpose, rights, format, and buyer decision. | Review inventory and agreed review boundary. |
| 2. Context and claim review | Assess whether each meaningful visual belongs on the page, accurately represents the nearby copy, and needs a caption or limitation. | Context/claim findings register. |
| 3. Accessibility and naming review | Review filenames, alt text, empty-alt decoration decisions, intrinsic dimensions, and visible text in graphics. | Asset-level metadata recommendations. |
| 4. Performance and delivery review | Assess format, dimensions, responsive candidates, loading priority, compression, and cache/CDN implications for the agreed pages. | Prioritized delivery and performance recommendations. |
| 5. Discovery metadata review | Assess representative `og:image`, Twitter metadata, structured data, and image sitemap opportunities only where accurate and useful. | Metadata recommendation set with no-guarantee notes. |
| 6. Implementation plan | Sequence highest-impact, lowest-risk actions with named owner and acceptance check. | 30/60/90-day implementation plan. |

## 4. Standard Deliverables

| Deliverable | Acceptance condition |
| --- | --- |
| Visual asset inventory for agreed pages | Every reviewed asset has a page, purpose, source/rights status, and action state. |
| Image SEO findings register | Each finding identifies evidence, risk/opportunity, recommendation, owner, and priority. |
| Filename and alt-text recommendation sheet | Recommendations describe actual visuals and do not contain keyword strings, fabricated facts, or unsupported claims. |
| Technical delivery recommendations | Format, dimensions, loading, responsive candidates, and caching recommendations are proportionate to actual asset use. |
| Preview and structured metadata review | Recommendations only use images visible and relevant to their page; no rich-result or platform-display guarantee is implied. |
| Implementation and measurement plan | The plan states what is controllable, what should be tested, and what external outcomes cannot be promised. |

## 5. Out of Scope Unless Added by Written Change

This bounded diagnostic does not include photography, illustration, headshot sessions, rights licensing, DAM migration, CDN migration, mass image conversion, CMS implementation, copywriting at scale, accessibility remediation beyond the reviewed pages, or ongoing measurement. These may be scoped separately only after the client confirms the relevant owner, access, timeline, and acceptance conditions.

## 6. Acceptance Review

The engagement is accepted when the client receives the agreed findings register and implementation plan, reviews the prioritization and facts, and can identify the owner for each next action. Acceptance does not depend on an image ranking, search-preview selection, traffic threshold, external AI result, or other third-party platform behavior.

## 7. Responsible Next Step

At close, recommend one of the following—not automatically an expanded implementation:

| Next step | Use when |
| --- | --- |
| Client-led remediation | The client has capable content/CMS owners and needs a clear backlog. |
| Bounded implementation | A small, testable set of changes can be accepted against agreed criteria. |
| Visual asset production scope | The audit found a genuine need for rights-cleared, explanatory visuals and the client can approve factual inputs. |
| No-go or defer | The evidence, rights, access, or business case is insufficient. |
